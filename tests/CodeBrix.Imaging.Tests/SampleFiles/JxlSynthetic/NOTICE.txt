These are original, programmatically constructed test images. The RGB sampling
fixtures were encoded with cjxl 0.11.2 and independently decoded with djxl 0.11.2
to float references. Source formulas, invocation flags, versions and hashes
are recorded in tools/jpeg-xl/generate-render-fixtures.py and manifest.json (Modular) or the vardct-, noise- and progressive-manifest.json files.
Tests read only the checked-in data and do not invoke those native tools.

integer31.jxl is a handwritten 2x1 grayscale Modular bitstream. It contains the
integer samples 1073741825 and 2147483647 at 31-bit precision, with no transforms
or restoration filters. tools/jpeg-xl/GeneratePrecisionFixture.cs records the
construction. djxl 0.11.2 independently accepted this 36-byte bitstream and
decoded its normalized float values as 0.5 and 1.0. The managed raw-plane test
checks the exact integers, which cannot both be represented exactly as float.

These resources are not included in the runtime NuGet package. The aggregate
JPEG XL resource budget includes this directory and JxlConformance.

Color/*.f32 are original pseudorandom RGBA inputs and skcms conversion results.
The profile data is read from the conformance images already attributed in
JxlConformance; no image pixels are reproduced in these color vectors.
Color/manifest.json records the native revision, input-profile hashes, format,
and resource hashes. GenerateCmsFixtures.cs and skcms-reference.cc record the
reproduction steps. Forward matrix/gray/CMYK and reverse CMYK conversions are
covered. Sampled destination curves are inverted exactly in the managed codec;
skcms fits those curves, so exact inversion is validated separately.

The PQ and HLG profiles in Color are synthesized BT.2020 profiles generated by
CodeBrix. Their vectors also exercise CICP precedence and the HDR reference OOTF.
The managed CMS evaluates exact transfer equations. skcms's fast approximations
amplify PQ error, especially near RGB gamut boundaries; PQ native comparisons
therefore use relative D50 PCS error (1% peak, 0.35% RMS), in addition to strict
independent luminance-point and round-trip checks of the exact equations.

The lut8/lut16 profiles are original non-cubic 2x3x4 lookup tables with matrix,
offset and curve stages in both directions. The native skcms comparison checks
their complete pipelines; unused trailing bytes accommodate skcms's vectorized
CLUT reads. Their construction is recorded in GenerateCmsFixtures.cs.

Jpeg contains 25 original arithmetic-pattern images encoded with cjpeg 2.1.5
and losslessly transcoded with cjxl 0.11.2. Native djxl confirmed byte equality
for every original JPEG, including progressive/restart, odd-size subsampling,
RGB/grayscale, 16-bit quantization, APP/COM/Exif/XMP, split ICC, fill, padding
and trailing bytes. generate-jpeg-fixtures.py records construction and hashes.
The split ICC case uses the original lut8 profile plus zero padding.

Hdr contains six original gradient/pattern images in PQ/HLG, encoded with the
pinned libjxl ef67fde2ec16d52e644c5a0969230b9a85e3eb31 reference build. Each has
original, sRGB and SDR outputs. sRGB/SDR references start from djxl linear-sRGB
output. tone-reference.cc invokes libjxl's scalar tone and gamut mappers; the
final sRGB transfer equation is evaluated exactly. This avoids djxl's combined
CMS/tone-stage behavior for non-XYB inputs and its rational sRGB approximation
outside 0..1. HDR sRGB comparisons use relative XYZ error because approximate
CMS transfer functions can cancel near RGB gamut boundaries. Original and SDR
comparisons use encoded component error. Limits are 0.0005 peak/0.0001 RMS;
physical HDR transfer points and tone-map endpoints are independently tested.
generate-hdr-fixtures.py records the build version, generation steps and hashes.
